# Mission Contract

Create this before substantive analysis.

```yaml
mission:
  outcome_required:
  decision_owner:
  affected_stakeholders: []
  why_now:
  current_state:
  constraints: []
  non_negotiables: []
  available_evidence: []
  source_boundaries: []
  known_unknowns: []
  required_deliverable:
  acceptance_criteria: []
  deadline:
  iteration_budget:
  human_checkpoint:
```

## Completeness rule

Ask a clarifying question only when the missing field changes the route, evaluation criteria, or permissible recommendation. Otherwise record a working assumption.

## Acceptance criteria examples

Good criteria are observable:

- “At least three mechanism-distinct concepts.”
- “Every recommendation linked to evidence or labelled assumption.”
- “One concept must pass consumer value, feasibility, and brand-distinctiveness thresholds.”
- “No recommendation may require more than the stated budget.”
- “Implementation plan names owner, dependency, timing, and leading indicator.”

Avoid vague criteria such as “innovative,” “excellent,” or “ground-breaking” unless operationalized.
